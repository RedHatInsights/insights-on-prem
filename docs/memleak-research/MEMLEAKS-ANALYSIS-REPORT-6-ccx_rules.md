## Top Allocation Hotspots

### 1. `inspect.getmodule()` — 30.3 GB (37% of total)

- **Location:** `inspect.py:1007` (17.3 GB), `inspect.py:1009` (13.0 GB)
- **Allocation count:** 504 million calls
- **Root cause:** `tests/conftest.py:61` — `wrap_add_filter()` calls `inspect.stack()[1][0].f_globals.get("__name__")` on every `add_filter()` invocation. `inspect.stack()` is extremely expensive — it captures the full call stack and resolves module info for every frame.
- **Impact:** This runs at import time for every rule component loaded by `dr.load_components()`. With hundreds of rules each calling `add_filter()`, this accumulates massive short-lived allocations.

### 2. YAML scanner — 6.6 GB (8% of total)

- **Location:** `yaml/scanner.py:286` (2.4 GB), `yaml/scanner.py:152` (2.3 GB), `yaml/scanner.py:153` (1.9 GB)
- **Allocation count:** 47.6 million from `stale_possible_simple_keys` alone
- **Root cause:** Every test case calls `InputData.add(spec, yaml_string)`, which parses YAML test data through PyYAML. With 2577 test cases each parsing one or more YAML documents, the scanner allocates heavily.
- **Impact:** These are short-lived per-test allocations — not a persistent leak, but a major contributor to peak memory and GC pressure.

### 3. YAML reader — additional overhead

- **Location:** `yaml/reader.py:89` (23.6M allocations), `yaml/reader.py:100` (18.7M allocations)
- **Root cause:** Same as above — character-by-character YAML reading for every test data file.

## Findings Linked to Prior Analysis

## Recommendations

1. **Replace `inspect.stack()` in `wrap_add_filter()`** with `sys._getframe(1)` — same caller module info at a fraction of the cost. This alone would eliminate 30 GB of allocations (~37% of total).

2. **Consider `yaml.CSafeLoader`** instead of the default Python YAML loader to reduce YAML parsing overhead.

3. **Profile individual rules** with `./run_memray_tests.sh -k "mcp_unexpected_on_disk_state"` to isolate the log object retention leak.

4. **Use `--aggregate` flag** for future full-suite runs to reduce profile file size (memray warned about this).
